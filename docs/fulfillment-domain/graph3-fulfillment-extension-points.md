# 履约域图三：能力扩展表

## 1. 文档说明

本文用于沉淀履约域首批建议开放的：

1. 内核标准能力选配与扩展点
2. 业务场景扩展能力选配与扩展点

说明：

- 这里只描述内核应暴露的能力接口
- 不关心具体业务线插件包实现
- 首批不把所有能力都开放，重点聚焦真正影响履约结果的核心能力
- 所有能力最终只回写本系统 `履约单`

---

## 2. 首批开放原则

### 2.1 内核标准能力开放原则

首批仅开放满足以下条件的能力：

- 业务线差异明显
- 对履约结果有实质影响
- 无法仅靠固定逻辑完全覆盖
- 能沉淀为稳定的内核能力接口

### 2.2 业务场景扩展能力开放原则

业务场景扩展能力只开放：

- 履约模式差异明确的能力
- 对外部执行系统下发或状态更新有明显差异的能力
- 可形成稳定模板选配的能力

不建议首批开放：

- 纯展示类能力
- 文案类能力
- 过细粒度的排序与装饰能力

## 5. 设计结论

图三的最终口径如下：

- 图三（一）只描述内核标准能力的首批开放策略
- 图三（二）只描述业务场景扩展能力的首批开放策略
- 内核标准能力与业务场景能力分层明确
- 所有能力最终只服务于 `履约单` 的状态、进度和外部引用更新
